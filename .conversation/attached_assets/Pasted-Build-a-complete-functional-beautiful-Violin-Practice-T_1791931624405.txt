Build a complete, functional, beautiful Violin Practice Tracker web app for a serious violin student. This must be a real working application, not just a mockup or a static dashboard.

1. Design and aesthetic

Create a polished, cozy, elegant musical aesthetic.

Use warm cream backgrounds, forest green accents, muted gold details, rounded cards, subtle shadows, and tasteful animations.

Use a clean, readable font and a beautiful display font for headings.

Make the interface feel like a premium productivity app designed specifically for musicians.

Ensure everything works on desktop, tablet, and mobile.

Include a sidebar on desktop and an appropriate navigation menu on smaller screens.

Avoid generic AI-generated dashboard styling. Give the app its own musical personality.

2. Dashboard

Create a home dashboard showing:

Today's total practice time.

This week's practice time.

A weekly practice goal with a progress bar.

Current practice streak.

Recent practice sessions.

Current repertoire and upcoming performance dates.

A prominent Start Practice button.

A quick summary of progress and achievements.

All statistics must be calculated from actual saved data, not hardcoded example numbers.

3. Practice session timer

Build a fully functional practice timer with:

Start, pause, resume, and finish controls.

A live elapsed-time display.

A way to select the piece being practised.

A way to select the practice category: technique, scales, intonation, bowing, sight-reading, repertoire, memorisation, or other.

Notes about what I worked on.

A field for recording goals and difficulties.

The ability to save completed sessions to practice history.

Accurate duration calculations that do not lose elapsed time when the timer is paused or the page is refreshed.

A confirmation before discarding an unfinished session.

4. Practice history and statistics

Create a detailed practice log with:

Date, duration, piece, category, and notes.

Filters for dates, pieces, and categories.

Daily, weekly, and monthly practice summaries.

Charts showing practice time over time.

Breakdown of time spent on each piece and category.

Personal records and milestones.

The ability to edit or delete sessions.

A calendar view showing practice activity.

Calculate all statistics from the underlying session records.

5. Repertoire manager

Allow me to manage my violin repertoire. Each piece should have:

Title and composer.

Practice status: learning, polishing, performance-ready, or completed.

Difficulty rating.

Current focus areas.

Personal notes.

Target performance date, if applicable.

Total practice time calculated automatically.

Number of sessions completed.

A progress indicator that I can update manually.

Allow pieces to be added, edited, archived, and deleted.

6. Goals and achievements

Implement:

Daily and weekly practice-time goals.

Goals for individual pieces.

Session-count goals.

Practice streak tracking.

Achievements for meaningful milestones.

A visual progress tracker.

Goals should encourage consistent, healthy practice rather than excessively long sessions. Never fabricate achievements or progress.

7. Practice planning

Create a practice planner where I can:

Plan what to practise each day.

Allocate time to different pieces and exercises.

Set specific goals for each practice block.

Mark planned blocks as completed.

Compare planned and actual practice time.

Rearrange or edit planned sessions.

Make the planner flexible enough for a student balancing school, lessons, rehearsals, and performances.

8. Data persistence

This is essential:

Save all user-created data persistently.

Use a suitable database supported by the Replit environment, preferably SQLite or another reliable persistent database.

Do not rely exclusively on React state or temporary in-memory storage.

Do not store all important information only in browser localStorage.

Make sure the application can be restarted without losing saved practice sessions, repertoire, goals, or plans.

Keep database operations organised and reliable.

9. Technical requirements

Use a maintainable, modern React and TypeScript architecture if appropriate for the Replit environment.

Build reusable components and keep the code organised.

Ensure all buttons, navigation items, forms, filters, and charts actually work.

Include sensible loading states, empty states, validation, and error handling.

Avoid unnecessary dependencies.

Do not leave placeholder pages, nonfunctional buttons, TODOs, or fake functionality.

Test the main user flows and fix errors before declaring the app complete.

10. GitHub compatibility

I intend to connect this project to GitHub and later continue development in Bolt.new.

Therefore:

Keep the project in a normal, portable Git repository.

Include a README with setup instructions.

Document environment variables and database setup.

Do not hardcode secrets.

Avoid unnecessary Replit-specific dependencies.

Make the app straightforward to run in another compatible development environment.

Ensure the source code, package configuration, and database schema are included in the repository.

Explain any deployment-specific requirements.

Implementation instructions

Build the application in working stages. Start by inspecting the environment, creating the project structure, implementing the database and core practice-tracking functionality, and then building the interface.

Prioritise a reliable, fully functional practice timer, persistent session history, repertoire management, and accurate statistics over flashy features.

Do not stop after producing a plan. Implement the application, run it, test it, and fix any errors you can identify. If a feature cannot be implemented reliably, explain why rather than pretending it works.
